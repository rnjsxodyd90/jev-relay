# Integration contract

## Library

`createInterpreter(options)` accepts server-side `jevKey`, `qwenKey`, `maxCalls`, `timeoutMs`, an optional trusted phrase-memory array, and injected provider adapters for tests. Jev is pinned to `jev-1.13.0`; the translator is `Qwen/Qwen3-30B-A3B-Instruct-2507`.

`interpret(input)` accepts:

```json
{
  "text": "Would you mind saying that again?",
  "context": "Formal singular address is required.",
  "source": "en",
  "target": "nl",
  "senseOptions": {}
}
```

Source text is bounded to 4,000 UTF-8 bytes; context to 2,000 characters; lexical alternatives to eight short IDs/descriptions. Lexical alternatives should come from trusted application/domain context. The prototype does not discover arbitrary word senses.

The four question IDs are stable: `action`, `memory`, `register`, `sense`. All returned IDs, probability keys, confidence ranges and distributions are validated before routing.

The returned `route` is one of:

| Route | Meaning | Downstream generation |
|---|---|---|
| `memory` | A stored phrase selected above the experimental threshold | Skipped |
| `translate` | New wording generated by Qwen | One Qwen call |
| `clarify` | Necessary context is unresolved | Skipped |
| `review` | Uncertain labels or an unavailable/invalid stage | No output approved |

The response includes `sourceText`, `translatedText`, `clarification`, `decisions`, `timing`, `model`, `reason`, and `usedTranslator`. Timing is current-call wall time, separate from recorded benchmark timings. Nothing is automatically spoken or externally acted upon.

## HTTP

- `GET /api/status`: configuration booleans and remaining request count, never key values.
- `GET /api/evidence`: frozen recorded inputs/results/statistics.
- `POST /api/interpret`: live input above. Requires `LIVE_MODE=1`, a server-side Jev key and matching local Origin.

Stable HTTP errors are JSON `{code,error}`. There is no key-upload API. The request body is limited to 16 KB and at most two live turns run concurrently. Provider calls time out, consume budget even when unsuccessful, and are not silently retried.

## Where to insert the gate

Use a single batch decision at a point where the application genuinely needs several semantic judgments. Examples include the interpreter's ambiguity/cache/register/sense gate, or an analogous support-ticket policy gate after separately validating that workload. Do not claim untested domains inherit this benchmark's accuracy or latency.

Prefer deterministic code for exact matches and unambiguous rules when possible. Evaluate embeddings/fuzzy matching and enum-constrained generative baselines for the real deployment workload before concluding Jev is the best option.

Native Jev `confidence` is a statistic of the full probability distribution, not the probability of the selected option or a calibrated chance of correctness. The parser validates its range separately rather than assuming equality. See https://docs.typesafe.ai/confidence. The recorded-contract test exercises all 36 real Jev bundle responses.
